# Гравигонки: конфигурация MVP

`rules.json` содержит силы, размеры болида, угловые ограничения, форсаж, повреждения и тайм-ауты. `tracks/red-canyon.json` содержит готовую геометрию трассы, стены, колонны, ориентированные ворота и старт. Клиент получает конфигурацию и SHA-256 от сервера при создании попытки; локальные JSON нужны для предварительного отображения терминала.

Координаты и радиусы измеряются в мировых единицах, скорости — в ед./с, ускорения — в ед./с², углы — в радианах. Ось X направлена вправо, Y — вниз. Курс 0 направлен вправо. Физический контур болида — окружность радиуса 0,9; декоративные кабели не участвуют в столкновениях. Один гоночный шаг составляет 1/60 секунды. Космос сохраняет частоту 20 Гц; сервер выполняет три гоночных подшага за мировой тик.

Трасса имеет длину 844 ед., основную ширину 8 ед. и технический участок шириной 6,2 ед. Центральная линия служит отображению и тестам проходимости; коллизии используют непрерывные стены и окружности препятствий. Ворота пересекаются только по направлению их `normal`, в порядке массива `checkpoints`, затем `finishLine`.

Для редактирования исходной формы измените углы и ширины в `tools/generate-race-track.py`, затем выполните из корня:

```powershell
python tools/generate-race-track.py
```

Можно редактировать готовый JSON непосредственно. После изменения геометрии повышайте `track.version`, после изменения сил, столкновений, тайм-аутов или зачёта — `rules.id` и `physicsVersion`, после изменения болида — `vehicleVersion`. Ключ таблицы: `trackId:trackVersion:rulesId:vehicleVersion:lapCount`. Перезапустите сервер и пересоберите клиент для обновления предварительного терминала. Конфигурация текущей попытки неизменяема; времена несовместимых версий не объединяются.

Общие проверочные векторы находятся в `shared/test-vectors/race.json`. Их генерирует серверная физика:

```powershell
$env:SRO_UPDATE_VECTORS='1'
dotnet test server/Sro.Sim.Tests --filter FullyQualifiedName~SharedVectorsMatchServer
Remove-Item Env:SRO_UPDATE_VECTORS
cd client
npm test -- src/race/physics.test.ts
```

Результаты записываются отдельно от экономики аккаунта, в `DataDir/race/results`. Сначала запись сбрасывается на диск и атомарно переименовывается, затем появляется в рейтинге. До успешной записи статус `PENDING`; сервер повторяет сохранение через 5 секунд. Таблицы восстанавливаются из результатов при запуске. Повторный запрос `raceAct/result` возвращает собственный серверный итог и не принимает время клиента. Гости не включаются в рейтинги, DNF учитывается только в лучшем завершённом круге, ABORT не учитывается ни в одной таблице.

Транспорт использует существующий авторизованный WebSocket `/ws`, протокол 40. Клиентские действия: `raceAct` с `act=join|ready|input|abort|result|leaderboard`. Сервер отвечает `raceEvent` с `event=joined|snapshot|result|leaderboard|error`. Для ввода обязательны возрастающий `seq`, полное состояние управления и монотонный `boostPressId`. Снимки включают подтверждённый `ackSeq`; позиции, HP и времена клиента сервер не принимает.
