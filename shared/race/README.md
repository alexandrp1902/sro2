# Гравигонки: конфигурация MVP

`rules.json` содержит силы, размеры болида, угловые ограничения, плавное торможение, повреждения и тайм-ауты. `tracks/red-canyon.json` содержит готовую геометрию трассы, стены, колонны, ориентированные ворота и старт. Клиент получает конфигурацию и SHA-256 от сервера при создании попытки; локальные JSON нужны для предварительного отображения терминала.

В версии физики 3 `throttle` задаёт долю выбранной скорости (0–1 от `engineLimit`), а не силу тяги. Регулятор постепенно разгоняет болид и снижает скорость с ограничением `coastBrakeAccel`; `brake` временно включает более сильное торможение с `brakeAccel`, сохраняя выбранную скорость. Форсаж удалён из физики и протокола гонок. На ПК W/↑ повышают скорость, S/↓ снижают, A/D/←/→ поворачивают, Пробел тормозит только пока зажат. Сенсорные органы управления скрыты на ПК. На смартфоне стик задаёт целевое направление, вертикальная шкала между стиком и тормозом задаёт скорость, правая кнопка тормозит только пока зажата.

Координаты и радиусы измеряются в мировых единицах, скорости — в ед./с, ускорения — в ед./с², углы — в радианах. Ось X направлена вправо, Y — вниз. Курс 0 направлен вправо. Физический контур болида — окружность радиуса 1,8. Болид увеличен вдвое и отображается сгенерированным PNG-спрайтом; медная и синяя окраски имеют одинаковую физику. Один гоночный шаг составляет 1/60 секунды. Космос сохраняет частоту 20 Гц; сервер выполняет три гоночных подшага за мировой тик.

Трасса версии 2 имеет длину 804 ед. и основную ширину около 32 ед. (примерно вчетверо шире исходной). Независимые скальные берега создают выступы, расширения и сужения: ширина меняется от 19 до 35,7 ед. Повороты сглажены для широкого проезда. Дорожное полотно рисуется по тем же берегам, которые используются для столкновений. Центральная линия служит навигации и тестам проходимости; коллизии используют непрерывные стены и окружности препятствий. Ворота охватывают ширину каньона и пересекаются только по направлению их `normal`, в порядке массива `checkpoints`, затем `finishLine`.

Для редактирования исходной формы измените углы и ширины в `tools/generate-race-track.py`, затем выполните из корня:

```powershell
python tools/generate-race-track.py
```

Можно редактировать готовый JSON непосредственно. После изменения геометрии повышайте `track.version`, после изменения сил, столкновений, тайм-аутов или зачёта — `rules.id` и `physicsVersion`, после изменения болида — `vehicleVersion`. Ключ таблицы: `trackId:trackVersion:rulesId:vehicleVersion:lapCount`. Перезапустите сервер и пересоберите клиент для обновления предварительного терминала. Конфигурация текущей попытки неизменяема; времена несовместимых версий не объединяются.

Общие проверочные векторы находятся в `shared/test-vectors/race.json`. Их генерирует серверная физика:

```powershell
$env:SRO_UPDATE_VECTORS='1'
dotnet test server/Sro.Sim.Tests --filter FullyQualifiedName~SharedVectorsMatchServer
Remove-Item Env:SRO_UPDATE_VECTORS
cd client
npm test -- src/race/physics.test.ts
```

Результаты записываются отдельно от экономики аккаунта, в `DataDir/race/results`. Сначала запись сбрасывается на диск и атомарно переименовывается, затем появляется в рейтинге. До успешной записи статус `PENDING`; сервер повторяет сохранение через 5 секунд. Таблицы восстанавливаются из результатов при запуске. Повторный запрос `raceAct/result` возвращает собственный серверный итог и не принимает время клиента. Гости не включаются в рейтинги, DNF учитывается только в лучшем завершённом круге, ABORT не учитывается ни в одной таблице.

Транспорт использует существующий авторизованный WebSocket `/ws`, протокол 40. Клиентские действия: `raceAct` с `act=join|ready|input|abort|result|leaderboard`. Сервер отвечает `raceEvent` с `event=joined|snapshot|result|leaderboard|error`. Для ввода обязательны возрастающий `seq` и полное состояние управления. Снимки включают подтверждённый `ackSeq`; позиции, HP и времена клиента сервер не принимает.
