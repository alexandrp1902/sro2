# M1 — модель полёта: чек-лист плейтеста

Цель этапа — чтобы полёт приятно ощущался на ПК и iPhone: разворот носом, инерция с гашением заноса, круиз, «залипающий» стик. Боя, NPC и лута пока нет.

## Как запустить

- ПК + iPhone по Wi-Fi: `tools\dev.ps1` → http://localhost:5173 и `http://<IP-ПК>:5173`.
- Через интернет: сборка + сервер + `tools\tunnel.ps1` (см. README).
- Без сервера: GitHub Pages без `?server=` — корабль летает локально на той же модели («локальный полёт» в статусе). Удобно, чтобы просто пощупать управление.

## Управление

**ПК**
- W / ↑ — газ, S / ↓ — тормоз, A / D / ← / → — поворот корпуса (с полной скоростью поворота класса).
- Отпустил газ или тормоз — корабль держит набранную скорость (круиз).
- Колесо мыши — тяга ±10%; `1`–`4` — 25 / 50 / 75 / 100%; `X` — стоп (тяга 0, корабль тормозит сам).
- Ctrl+колесо, щипок на тачпаде или `+` / `−` — зум.
- `` ` `` (Ё) или клик по строке скорости справа вверху — dev-панель.

**iPhone**
- Стик слева внизу: направление — куда отведена ручка, тяга — насколько далеко. Отпустил палец — ручка остаётся на месте.
- Двойной тап по стику — стоп, ручка возвращается в центр.
- Щипок двумя пальцами по экрану — зум. Тап по строке скорости — dev-панель.

## Проверки

- [ ] Все три класса (dev-панель → Лёгкий / Средний / Тяжёлый) на ПК и на iPhone.
- [ ] Разворот на 180°: корабль не летит кормой вперёд, а разворачивается носом и гасит старую скорость.
- [ ] Повороты на полной скорости: не ощущаются ли торможением (см. «Что крутить»).
- [ ] Остановиться внутри зелёного круга «парковка» под станцией — сначала лёгким, потом тяжёлым.
- [ ] Слалом между оранжевыми буями справа от станции.
- [ ] Стик: ручка остаётся на месте, если увести палец за пределы стика или свернуть Пункт управления.
- [ ] Двойной тап по стику останавливает; обычное управление стиком случайно не останавливает.
- [ ] Медленное точное движение: ручка чуть дальше мёртвой зоны — корабль ползёт.
- [ ] ПК: W разгоняет, S тормозит, отпустил — скорость держится; A/D крутят корпус и на месте, и на ходу.
- [ ] Указатель желаемого направления у корабля помогает тяжёлому.
- [ ] Щипок и Ctrl+колесо меняют зум, страница браузера не зумится.
- [ ] Предсказание: в dev-панели «коррекция» ≈ 0 и «щелчков» 0 — и с имитацией лага 200 мс.
- [ ] Через tunnel (мобильная сеть): управление не «вязкое», корабль не дёргается.
- [ ] ПК и iPhone одновременно: видят корабль друг друга (оранжевый), он движется плавно.
- [ ] Горячая правка `shared/hulls.json` во время полёта: изменение чувствуется через ~1 с без перезапуска (в логе сервера `hulls.json reloaded`).

## Что крутить в `shared/hulls.json`

Сервер перечитывает файл на лету и рассылает клиентам. Невалидный файл отклоняется целиком (предупреждение в логе сервера), старые значения остаются.

| Параметр | Что меняет |
|---|---|
| `maxSpeed` | максимальная скорость |
| `acceleration` | как быстро набирает скорость |
| `brakeAcceleration` | как быстро тормозит (стоп, снижение тяги, гашение обратной скорости после разворота) |
| `turnRate` | скорость разворота носом, °/с |
| `lateralDampTime` | за сколько секунд гасится занос (до ~5%) |
| `lateralToForward` | 0…1: доля погашенного заноса, которая переходит в скорость вперёд |
| `size` | размер силуэта (только визуал) |

**Повороты и скорость.** При `lateralToForward = 0` (как в документе: занос просто гасится) скорость в поворотах немного теряется. После снижения `maxSpeed` вдвое (330/250/170 → 165/125/85) потери стали небольшими:

| | поворот на 90° с полной скорости | непрерывный вираж |
|---|---:|---:|
| лёгкий (165) | 156 (95%) | 139 (84%) |
| средний (125) | 121 (97%) | 121 (97%) |
| тяжёлый (85) | 84 (99%) | 83 (98%) |

При прежних скоростях лёгкий в вираже падал до 42%. Если вираж всё же ощущается как торможение — поставьте `lateralToForward` 0.3–0.5: при 0.5 скорость в вираже почти не теряется.

## Отличия реализации от документа v0.2

- Скорость тянется к `MaxSpeed·Throttle` (§7, §11), а не растёт бесконечно по §55 (`Velocity += Forward·Acceleration·Throttle·dt`).
- Тяга не разгоняет суммарную скорость вместе с заносом выше `MaxSpeed·Throttle`: иначе на виражах корабль летел бы быстрее максимума.
- Тяга стика — кривая `^1.5` с мёртвой зоной 10% (§28–29), а не линейная `StickMagnitude` из §55.
- Боковое гашение (§17–18) — экспонента: за `lateralDampTime` остаётся ~5%. При нулевой тяге занос дополнительно гасится тормозом (§55).
- `lateralToForward` — новый параметр, в документе его нет.
- ПК-управление — «танковое» из GDD §7 (W — газ, S — тормоз, A/D — поворот), а не направление на экране из §21–25: так решили после первого плейтеста. Заднего хода по-прежнему нет. Стик на смартфоне остался по v0.2.
