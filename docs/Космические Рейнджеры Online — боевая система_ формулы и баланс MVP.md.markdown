# Космические Рейнджеры Online
## Боевая система — формулы и баланс MVP

**Версия:** 0.2

> В версии 0.2 изменена модель управления кораблем. Корабль не может двигаться боком или назад. Игрок задает желаемое направление движения и величину тяги, после чего корабль физически разворачивается в эту сторону и летит носом вперед.

---

# 1. Базовый принцип движения

У корабля отсутствуют:

- движение боком;
- стрейф;
- движение задним ходом;
- мгновенное изменение направления движения.

Корабль всегда движется **носом вперед**.

Игрок фактически задает две величины:

```text
DesiredDirection
Throttle
```

Где:

```text
DesiredDirection = желаемое направление движения
Throttle = 0.0 ... 1.0
```

Корабль сначала поворачивается в сторону `DesiredDirection`, а затем создает тягу вперед.

---

# 2. Почему используется такая система

Основными характеристиками управления становятся:

```text
MaxSpeed
Acceleration
TurnRate
Inertia
```

Поэтому разные корабли действительно ощущаются по-разному.

Легкий истребитель:

- быстро разворачивается;
- быстро набирает скорость;
- быстро меняет направление.

Тяжелый корабль:

- медленно разворачивается;
- имеет большую инерцию;
- медленно меняет вектор движения.

---

# 3. Управление на смартфоне

В нижней левой части экрана располагается виртуальный стик.

Пример:

```text
┌───────────────────────┐
│                       │
│                       │
│        КОРАБЛЬ        │
│           ▲           │
│                       │
│                       │
│                       │
│    ◉              ●   │
│   СТИК          АТАКА │
└───────────────────────┘
```

Стик управляет одновременно:

1. направлением;
2. скоростью движения.

---

# 4. Направление стика

Направление от центра стика до ручки определяет желаемое направление полета.

Например:

```text
        ↑
        │
    ↖   │   ↗
      \ │ /
←────── ● ──────→
      / │ \
    ↙   │   ↘
        │
        ↓
```

Если игрок отводит стик вправо:

```text
DesiredDirection = вправо
```

Корабль начинает разворачиваться вправо.

После разворота он продолжает лететь носом вперед в этом направлении.

---

# 5. Положение стика фиксируется

Стик работает не как обычный мобильный джойстик, который обязательно удерживать пальцем.

После того как игрок:

1. коснулся стика;
2. отвел ручку в нужное положение;
3. отпустил палец,

ручка **остается в выбранном положении**.

Следовательно, корабль продолжает движение без необходимости постоянно держать палец на экране.

Это особенно важно для игры одной рукой и длительных перелетов внутри системы.

---

# 6. Величина отклонения стика

Расстояние ручки от центра задает тягу.

```text
Throttle =
StickDistance / StickMaxDistance
```

Ограничение:

```text
0.0 ≤ Throttle ≤ 1.0
```

Например:

```text
Стик в центре       = 0%
Небольшое отклонение = 25%
Половина             = 50%
Почти до края        = 80%
До края              = 100%
```

---

# 7. Скорость от положения стика

Желаемая скорость:

```text
DesiredSpeed =
MaxSpeed × Throttle
```

Например корабль имеет:

```text
MaxSpeed = 300
```

Стик установлен на 30%:

```text
DesiredSpeed = 90
```

Стик установлен на 70%:

```text
DesiredSpeed = 210
```

Стик полностью отведен:

```text
DesiredSpeed = 300
```

---

# 8. Центр стика

Если ручка находится точно по центру:

```text
Throttle = 0
```

Корабль перестает создавать тягу.

После этого он начинает постепенно тормозить за счет системы стабилизации.

То есть остановка происходит **не мгновенно**.

---

# 9. Двойной тап по стику

Для быстрого сброса тяги используется:

**двойной тап по зоне стика.**

После двойного тапа:

```text
StickPosition = Center
Throttle = 0
```

Ручка визуально возвращается в центр.

Корабль начинает торможение.

Это мобильный аналог команды:

**«Стоп».**

---

# 10. Торможение

Хотя отдельного движения назад нет, корабль способен тормозить внутренними маневровыми двигателями.

Это не является полноценным задним ходом.

Используется только для уменьшения текущей скорости.

Формула:

```text
CurrentSpeed =
max(
    0,
    CurrentSpeed - BrakeAcceleration × dt
)
```

Когда:

```text
Throttle = 0
```

система автоматически включает торможение.

---

# 11. Инерция

Изменение скорости происходит постепенно.

Нельзя мгновенно перейти:

```text
300 → 0
```

или:

```text
0 → 300
```

Основная формула:

```text
CurrentSpeed =
MoveTowards(
    CurrentSpeed,
    DesiredSpeed,
    Acceleration × dt
)
```

При торможении может использоваться отдельный параметр:

```text
BrakeAcceleration
```

---

# 12. Рекомендуемые параметры

| Класс | MaxSpeed | Acceleration | BrakeAcceleration |
|---|---:|---:|---:|
| Легкий | 330 | 180 | 220 |
| Средний | 250 | 120 | 145 |
| Тяжелый | 170 | 70 | 80 |
| Линкор | 120 | 40 | 45 |

Легкий корабль быстро меняет темп движения.

Линкор требует заранее планировать маневр.

---

# 13. Разворот корабля

Корабль не меняет направление мгновенно.

Есть параметр:

```text
TurnRate
```

измеряемый в:

```text
градусах в секунду
```

Например:

| Класс | TurnRate |
|---|---:|
| Легкий | 150°/с |
| Средний | 100°/с |
| Тяжелый | 55°/с |
| Линкор | 30°/с |

---

# 14. Формула поворота

Игрок задает:

```text
DesiredDirection
```

Из него вычисляется:

```text
DesiredAngle
```

Корабль изменяет угол:

```text
Rotation =
MoveTowardsAngle(
    Rotation,
    DesiredAngle,
    TurnRate × dt
)
```

Поэтому тяжелый корабль не может моментально развернуться на 180°.

---

# 15. Движение во время разворота

Очень важный принцип:

**текущая скорость не меняет направление мгновенно вместе с корпусом.**

Корабль обладает инерцией.

Например, корабль летел:

```text
→
```

Игрок поставил стик:

```text
↑
```

Корабль начинает разворачиваться:

```text
→
↗
↑
```

При этом некоторое время он продолжает смещаться по старому вектору.

Получается плавная космическая дуга.

---

# 16. Вектор скорости

У корабля хранится:

```text
VelocityVector
```

Тяга прикладывается только по направлению носа:

```text
ForwardVector =
DirectionFromRotation(Rotation)
```

```text
Velocity +=
ForwardVector
× Thrust
× dt
```

Это принципиально важное отличие от управления персонажем.

Игрок не перемещает объект напрямую.

Он управляет **кораблем с собственной физикой**.

---

# 17. Стабилизация боковой инерции

Не следует делать полностью ньютоновскую физику, иначе управление на смартфоне станет слишком сложным.

Поэтому используется автоматическая стабилизация бокового скольжения.

Компонента скорости, не совпадающая с направлением корпуса, постепенно уменьшается.

Пример:

```text
LateralVelocity *= LateralDamping
```

Это создает ощущение инерции, но корабль через некоторое время выравнивает траекторию по направлению носа.

---

# 18. Рекомендуемая сила инерции

Для MVP:

### Легкий

Боковая инерция исчезает примерно за:

```text
0.5–0.8 сек
```

### Средний

```text
0.8–1.2 сек
```

### Тяжелый

```text
1.2–1.8 сек
```

### Линкор

```text
1.5–2.5 сек
```

Точные значения определяются playtest.

---

# 19. Разворот на 180 градусов

Если корабль летит вправо:

```text
→
```

а игрок переводит стик влево:

```text
←
```

корабль НЕ начинает лететь кормой вперед.

Вместо этого он:

1. начинает разворот;
2. продолжает некоторое время двигаться по инерции;
3. постепенно гасит старый вектор;
4. разворачивается носом;
5. начинает ускоряться в новом направлении.

Это один из ключевых элементов управления.

---

# 20. Отсутствие заднего хода

Команда:

```text
MoveBackward
```

в игре отсутствует.

Также отсутствует:

```text
StrafeLeft
StrafeRight
```

Любая команда движения означает:

> «Развернуть корабль носом в заданную сторону и двигаться туда вперед».

---

# 21. Управление с ПК

На ПК необходимо сохранить ту же физическую модель, что и на смартфоне.

WASD и стрелки задают **желаемое направление на экране**, а не тягу отдельных двигателей.

```text
W / ↑ = направление вверх
S / ↓ = направление вниз
A / ← = направление влево
D / → = направление вправо
```

Комбинации:

```text
W + D = ↗
W + A = ↖
S + D = ↘
S + A = ↙
```

---

# 22. Поведение ПК-управления

Например корабль смотрит:

```text
↑
```

Игрок нажимает:

```text
D
```

Это НЕ означает движение боком вправо.

Устанавливается:

```text
DesiredDirection = →
```

Корабль начинает поворачиваться:

```text
↑
↗
→
```

и только после этого его тяга направляется вправо.

---

# 23. Скорость на ПК

Поскольку клавиатура не позволяет аналоговое управление, при удержании направления используется:

```text
Throttle = 100%
```

Но игрок может регулировать маршевую скорость отдельными клавишами.

Рекомендуемый вариант:

```text
1 = 25%
2 = 50%
3 = 75%
4 = 100%
```

Либо колесом мыши:

```text
Wheel Up   = увеличить тягу
Wheel Down = уменьшить тягу
```

Для MVP предпочтительно колесо мыши.

---

# 24. Остановка на ПК

Команда:

```text
X
```

или:

```text
Space при отсутствии выбранной боевой цели
```

не рекомендуется, поскольку Space нужен для стрельбы.

Поэтому фиксируется:

```text
X = Stop
```

После нажатия:

```text
Throttle = 0
```

Корабль начинает автоматическое торможение.

---

# 25. Сохранение установленной тяги

Как и мобильный стик, управление ПК может иметь режим круизного движения.

Игрок устанавливает направление и тягу.

После отпускания кнопок корабль продолжает движение.

То есть не требуется постоянно держать:

```text
W
```

во время полета через большую систему.

Нажатие другой комбинации направления меняет:

```text
DesiredDirection
```

---

# 26. Стик и указатель направления

При установленном стике около корабля можно отображать небольшой полупрозрачный указатель:

```text
        ↗
       /
      ▲
   корабль
```

Он показывает:

**куда корабль в данный момент пытается повернуть.**

Это особенно полезно для тяжелых кораблей с медленным поворотом.

---

# 27. Мобильный стик

Рекомендуемая геометрия:

```text
OuterRadius = 60–75 px
InnerHandle = 25–35 px
```

Фактические размеры рассчитываются относительно DPI устройства.

Стик располагается:

```text
нижняя левая четверть экрана
```

с отступом от краев.

---

# 28. Dead Zone

Чтобы небольшой случайный сдвиг ручки не заставлял корабль двигаться:

```text
DeadZone = 8–12%
```

Если:

```text
StickDistance < DeadZone
```

то:

```text
Throttle = 0
```

---

# 29. Кривая чувствительности стика

Не рекомендуется линейное управление скоростью.

Для точного медленного движения около:

- станции;
- ресурсов;
- других кораблей,

нужна повышенная чувствительность около центра.

Рекомендуемая формула:

```text
Throttle =
NormalizedStickDistance ^ 1.5
```

Примерно:

```text
20% отклонения → 9% тяги
40% → 25%
60% → 46%
80% → 72%
100% → 100%
```

Это позволяет очень точно двигаться медленно.

---

# 30. Snap to Center

При двойном тапе:

```text
StickX = 0
StickY = 0
Throttle = 0
```

Анимация возврата ручки:

```text
100–150 мс
```

Само изменение тяги происходит сразу.

---

# 31. Защита от случайного двойного тапа

Двойной тап определяется как:

```text
TapCount = 2
```

с интервалом:

```text
<= 300 мс
```

и перемещением между тапами не более:

```text
20–30 px
```

Так обычное управление стиком не будет случайно восприниматься как команда остановки.

---

# 32. Потеря касания

Если палец ушел за пределы стика:

текущее положение стика **не сбрасывается**.

После `touchend`:

```text
StickPosition = LastPosition
```

Игрок должен:

- передвинуть его снова;
- либо выполнить двойной тап для остановки.

---

# 33. Боевой смысл управления скоростью

Неполная тяга нужна не только для удобства.

Она становится частью боя.

Например, игрок может:

- снизить скорость перед противником;
- удерживать оптимальную дальность оружия;
- медленно кружить вокруг станции;
- синхронизировать скорость с союзником;
- собрать несколько ресурсов;
- не пролететь мимо цели.

---

# 34. Орбитального стрейфа нет

Корабль не способен лететь боком и одновременно держать нос постоянно направленным на противника.

Следовательно, направление оружия необходимо учитывать отдельно.

Для базового MVP все основные орудия имеют достаточно широкий сектор наведения.

Например:

```text
WeaponArc = ±60°
```

от направления корпуса.

---

# 35. Сектор стрельбы

Если выбранная цель находится слишком далеко сбоку или сзади корабля:

оружие не стреляет.

Проверяется:

```text
TargetAngle
```

Если:

```text
abs(TargetAngle) <= WeaponArc
```

оружие может стрелять.

Например:

```text
WeaponArc = 60°
```

дает общий сектор:

```text
120°
```

в передней части корабля.

---

# 36. Зачем нужен сектор оружия

Без ограничения сектора игрок мог бы:

- улетать от противника;
- стрелять назад;
- практически не учитывать разворот корабля.

Сектор оружия связывает:

```text
маневрирование
+
стрельбу
```

в единую боевую механику.

---

# 37. Ракеты

Ракеты являются исключением.

После запуска они могут самостоятельно доворачивать к выбранной цели.

Но запуск все равно разрешается только если цель находится в передней полусфере:

```text
LaunchArc = ±90°
```

---

# 38. Турельное оружие

В дальнейшем тяжелые корабли могут получать специальные турельные слоты.

Например:

```text
TurretArc = 360°
```

Это становится преимуществом больших кораблей.

Но турельные пушки:

- слабее;
- тяжелее;
- потребляют больше энергии.

Для MVP такие слоты необязательны.

---

# 39. Обновленная модель уклонения

Система движения хорошо сочетается с уклонением.

Базовое:

```text
TotalEvasion =
BaseEvasion
+ MovementEvasion
+ ModuleBonus
```

MovementEvasion зависит от текущей скорости.

```text
SpeedRatio =
CurrentSpeed / MaxSpeed
```

```text
MovementEvasion =
MaxMovementEvasion × SpeedRatio
```

---

# 40. Movement Evasion

Рекомендуется:

| Класс | Max Movement Evasion |
|---|---:|
| Легкий | +8% |
| Средний | +5% |
| Тяжелый | +2% |
| Линкор | 0% |

Поэтому остановившийся легкий корабль становится заметно проще поразить.

---

# 41. Пример

Легкий корабль:

```text
BaseEvasion = 25%
```

Он летит на полной скорости:

```text
MovementEvasion = 8%
```

Итого:

```text
TotalEvasion = 33%
```

Если игрок остановился:

```text
TotalEvasion = 25%
```

---

# 42. Boost

Boost не меняет модель управления.

Во время Boost:

```text
MaxSpeed × 1.4
Acceleration × 1.5
```

Продолжительность:

```text
3 сек
```

Игрок продолжает управлять направлением через стик.

При этом ограничение `TurnRate` сохраняется.

Таким образом тяжелый корабль не превращается при Boost в сверхманевренный.

---

# 43. Boost и инерция

После завершения Boost корабль не мгновенно падает до обычной максимальной скорости.

Он постепенно тормозит до:

```text
NormalMaxSpeed
```

Это создает приятное ощущение разгона.

---

# 44. Подбор ресурсов

Для точного подбора предметов игрок может:

1. тапнуть по ресурсу;
2. установить небольшую тягу стиком;
3. медленно приблизиться;
4. войти в `PickupRange`;
5. тракторный луч автоматически заберет предмет.

Наличие аналоговой скорости особенно полезно именно здесь.

---

# 45. Автопилот к ресурсу

В MVP тап по ресурсу **не должен автоматически управлять кораблем**.

Тап только устанавливает:

```text
SelectedLoot
```

Игрок сам подлетает к объекту.

Это сохраняет важность управления кораблем.

---

| Movement Evasion | 8% | 5% | 2% |
| Cargo | 20 | 50 | 100 |

# 48. Серверное состояние движения

Сервер хранит:

```text
MovementState {
    position

    rotation

    velocityX
    velocityY

    desiredDirection

    throttle

    maxSpeed
    acceleration
    brakeAcceleration
    turnRate
}
```

---

# 49. Команда клиента

Клиент не должен отправлять серверу свои координаты.

Он отправляет только управление:

```text
MOVE_INPUT {
    directionX
    directionY
    throttle
}
```

Например:

```text
directionX = 0.707
directionY = -0.707
throttle = 0.65
```

означает:

```text
↗
65% тяги
```

---

# 50. Команда остановки

Двойной тап мобильного стика отправляет:

```text
SET_THROTTLE {
    throttle: 0
}
```

Сервер продолжает самостоятельно рассчитывать торможение и инерцию.

---

# 51. Server authoritative movement

Сервер проверяет:

```text
Throttle <= 1
TurnRate <= HullTurnRate
Acceleration <= HullAcceleration
Speed <= допустимого значения
```

Поэтому чит-клиент не может просто отправить себе:

```text
Speed = 10000
```

---

# 52. Интерполяция

Клиент визуально предсказывает движение собственного корабля.

Сервер периодически присылает:

```text
Position
Rotation
Velocity
```

При небольшой разнице клиент плавно корректирует траекторию.

При большой:

```text
ServerState
```

имеет приоритет.

---

# 53. Главный принцип управления

Управление должно ощущаться как:

> «Я задаю кораблю, куда и насколько быстро я хочу лететь, а корабль физически выполняет этот маневр».

Но не как:

> «Я непосредственно двигаю объект по экрану джойстиком».

---

# 54. Итоговое управление смартфона

Основная схема:

```text
Стик в направлении
→ корабль разворачивается туда.

Чем дальше стик от центра
→ тем выше желаемая скорость.

Отпустить палец
→ положение стика сохраняется.

Вернуть стик ближе к центру
→ снизить скорость.

Стик в центре
→ остановка с учетом инерции.

Двойной тап по стику
→ мгновенно установить стик в центр.

Тап по противнику
→ выбрать цель.

Кнопка Attack
→ открыть огонь.

Тап по ресурсу
→ выбрать ресурс для подбора.
```

---

# 55. Итоговая модель движения

Математически управление можно представить так:

```text
Throttle =
StickMagnitude
```

```text
DesiredSpeed =
MaxSpeed × Throttle
```

```text
DesiredAngle =
atan2(
    StickY,
    StickX
)
```

```text
Rotation =
MoveTowardsAngle(
    Rotation,
    DesiredAngle,
    TurnRate × dt
)
```

```text
Forward =
VectorFromAngle(Rotation)
```

```text
Velocity +=
Forward
× Acceleration
× Throttle
× dt
```

при отсутствии тяги:

```text
Velocity =
MoveTowards(
    Velocity,
    0,
    BrakeAcceleration × dt
)
```

и постоянно действует умеренное подавление боковой скорости:

```text
LateralVelocity *= LateralDamping
```

Именно эта модель используется одновременно на ПК и смартфоне.
