# Космические Рейнджеры Online

Браузерная многопользовательская космическая action-RPG с видом сверху для ПК и смартфона.
Дизайн-документы лежат в [docs/](docs/).

- **Сервер:** .NET 10, ASP.NET Core WebSockets, авторитарная симуляция 20 тиков/с — [server/](server/)
- **Клиент:** TypeScript + PixiJS + Vite — [client/](client/)

## Требования

- .NET SDK 10
- Node.js 24
- для игры через интернет — `cloudflared` (`winget install Cloudflare.cloudflared`)

## Разработка

Один раз установить зависимости клиента:

```powershell
cd client
npm install
```

Запустить игровой сервер и Vite (каждый откроется в отдельном окне):

```powershell
powershell -ExecutionPolicy Bypass -File tools\dev.ps1
```

- ПК: http://localhost:5173
- iPhone в той же Wi-Fi сети: `http://<IP-ПК>:5173` (скрипт печатает адрес)

При первом запуске Windows спросит разрешение для `dotnet` и `node`: разрешите доступ в **частных сетях**. Профиль вашей Wi-Fi сети тоже должен быть «Частная».

## Управление

- **ПК:** W / ↑ — газ, S / ↓ — тормоз, A / D / ← / → — поворот корпуса; без газа и тормоза корабль держит набранную скорость. Колесо мыши — тяга ±10%, `1`–`4` — 25/50/75/100%, `X` — стоп. Зум — Ctrl+колесо или `+`/`−`.
- **Смартфон:** стик слева внизу задаёт направление и тягу и остаётся там, где его отпустили; двойной тап по стику — стоп; щипок — зум.
- **Бой:**
  - цель — клик или тап по кораблю или по его стрелке у края экрана (стрелка выбранной цели обведена оранжевым); Esc или ✕ на карточке — снять цель;
  - предыдущий / следующий объект: Q / E, Shift+← / Shift+→, Shift+Tab / Tab; на смартфоне — кнопки `<` и `>` по бокам от «ОГОНЬ». Перебираются и корабли, и добыча;
  - **прицел один:** он либо на противнике, либо на грузе. Навелись на груз — цель снимается и огонь гаснет, и наоборот;
  - порядок перебора — по спирали: ближнее кольцо обходится по часовой стрелке, затем следующее. Список закольцован, на крайнем объекте не упирается; с пустого выбора начинает с ближайшего;
  - огонь — переключатель: Space, кнопка «ОГОНЬ» или двойной клик / тап по цели включают, повторное нажатие выключает; пока включён, пушка стреляет сама по готовности. Включённая кнопка горит красным, на ПК под карточкой цели — «ОГОНЬ ПО ГОТОВНОСТИ» в красной рамке;
  - огонь без цели берёт ближайший корабль, снятие цели выключает огонь;
  - пушки бьют в любую сторону, разворачиваться к цели не нужно (сектор — `arc` в `weapons.json`: 180 — во все стороны, 60 — ±60° от носа);
  - дистанция до цели — в **секторах**: 1 сектор ≈ дальность пушки по умолчанию и примерно половина экрана телефона. Дальше 1 сектора большинство пушек уже не достаёт;
  - у пушек разные профили точности: лазер бьёт почти без промаха вблизи, но не достаёт дальше 500; плазма достаёт дальше всех, зато в упор мажет.
- **Добыча:**
  - предмет выбирается кликом или тапом, на ПК `F` наводится на ближайший;
  - тап по предмету кораблём не управляет: подлетайте сами, автопилота нет;
  - подобрать — **пробел** (или кнопка «ВЗЯТЬ», в которую превращается «ОГОНЬ», пока прицел на грузе): надо подлететь в радиус захвата, сам луч ничего не хватает;
  - `Esc` снимает сначала выбранный предмет или станцию, потом цель — и возвращает пробелу огонь;
  - трюм — панель слева под полосками, тап разворачивает список; ёмкость зависит от корпуса;
  - груз продают в доке станции.
- **Станция:** выбирается прицелом, как корабль или груз, — тапом, кликом, Q / E; вокруг неё зелёные уголки, внизу карточка с дистанцией. Стрелять в неё нельзя: пока прицел на станции, пробел (на телефоне — кнопка огня, подписанная «ДОК») стыкует, если корабль в зелёном круге, а издалека просит подлететь ближе. Корабль уходит в док — из космоса, из прицелов и с пути метеоритов, — и открывается экран станции: «Груз» (продажа), «Корабли» и «Оружие» (покупка и смена), ремонт корпуса. «Вылет» или пробел — корабль появляется там же, стоя, с защитой, как после появления.
- **Метеориты:** идут через систему по дуге — их ведёт тяготение центра, — кувыркаются по трём осям и таранят всё, что не свернуло. Траектории разные и выпадают по вероятностям, появления — не по расписанию. Предупреждения нет: камень надо замечать самому. Крупный в лоб не сбить — от него уворачиваются; расстрелянный роняет минералы. В укрытие у станции камни не залетают.
- **Пираты:** живут в логовах (красные круги на карте) и нападают на игроков, которые подлетели ближе 700. Пират, который целится в вас, помечен «!», в HUD — «под атакой: N». Пунктирный круг вокруг станции — укрытие: туда пираты не залетают и бросают погоню.
- `` ` `` (Ё) или тап по строке скорости — dev-панель: сеть, скорость, ошибка предсказания, задержка чужих кораблей, имитация лага. Корпус и пушку меняют в доке.
- Тап по строке статуса — окно «Пилот»: вход, выход и адрес игрового сервера.

## Аккаунты

Вход — по нику и паролю; новый ник с паролем сам заводит аккаунт. Пароль вводится один раз: устройство получает ключ и дальше входит по нему — после обрыва связи, перезагрузки вкладки, перезапуска сервера. Тот же ник и пароль работают на любом устройстве: начали на ПК, продолжили с телефона тем же кораблём (GDD §61). Если корабль уже в игре с другого устройства, новый вход забирает его, а первое устройство пишет «корабль на другом устройстве» и само не переподключается.

В аккаунте хранятся кредиты, купленные корпуса и пушки, что стоит на корабле, и трюм. Положение не хранится: после входа корабль появляется у станции. После обрыва связи корабль по-прежнему 60 с ждёт в космосе.

Сервер держит аккаунты в `data/accounts/<id>.json` (папка вне git, путь — `DataDir` в `server/Sro.Server/appsettings.json`) и сбрасывает изменения на диск раз в секунду. Пароль хранится как PBKDF2, ключи устройств — как SHA-256. Удалить аккаунт — удалить его файл при остановленном сервере.

Без пароля и ключа сервер пускает гостем — без сохранения и со всем ангаром сразу. Так входят тесты и смоук-скрипты; в игре такого входа нет.

Баланс лежит в семи файлах:
- [shared/hulls.json](shared/hulls.json) — корпуса: полёт, прочность, щит, уклонение, ёмкость трюма;
- [shared/weapons.json](shared/weapons.json) — пушки;
- [shared/combat.json](shared/combat.json) — респаун, защита после появления, дроны;
- [shared/npcs.json](shared/npcs.json) — пираты: типы, уровни, логова, радиусы агро, погони и укрытия;
- [shared/loot.json](shared/loot.json) — добыча: предметы, таблицы дропа, контейнеры, радиус захвата, сдача груза;
- [shared/meteors.json](shared/meteors.json) — метеориты: размеры, прочность, скорости, тяготение, траектории, урон тарана;
- [shared/shop.json](shared/shop.json) — станция: стартовые кредиты, цены корпусов и пушек, цена ремонта.

Сервер подхватывает правки на лету, без перезапуска. Невалидный файл отклоняется, и остаётся прежний баланс.

## Тесты

```powershell
dotnet test server/Sro.sln    # полёт, бой, очередь входов, комната: сессии, выстрелы, уничтожение, респаун, дроны, ИИ пиратов, аккаунты, док
cd client; npm test           # те же формулы на TS, стик, клавиатура, выбор цели, предсказание, интерполяция
node tools/smoke.mjs          # сквозная проверка полёта с запущенным сервером
node tools/smoke-mp.mjs       # сквозная проверка мультиплеера: ники, обрыв и возврат, дубль вкладки
node tools/smoke-combat.mjs   # сквозная проверка боя: защита, темп огня, щит и корпус, сектор (~20 с)
node tools/smoke-pve.mjs      # сквозная проверка пиратов: агро у логова, огонь, погоня, укрытие (~1 мин)
node tools/smoke-loot.mjs     # сквозная проверка добычи: дроп, подбор, трюм, продажа в доке (~1 мин)
node tools/smoke-meteor.mjs   # сквозная проверка метеоритов: дуга, обстрел, минералы, укрытие (~1-2 мин)
node tools/smoke-account.mjs  # сквозная проверка аккаунта и станции: вход, отказы, док, покупка, возврат по ключу (~20 с)
```

Модель полёта и формулы боя написаны дважды: на C# для сервера и на TS для клиента (предсказание и карточка цели). Их совпадение проверяют эталоны в [shared/test-vectors/](shared/test-vectors/). После изменения формул эталоны нужно перегенерировать: `$env:SRO_UPDATE_VECTORS='1'; dotnet test server/Sro.sln`.

## Игра по Wi-Fi без dev-сервера

```powershell
cd client; npm run build; cd ..
dotnet run --project server/Sro.Server
```

Сервер сам отдаёт собранный клиент: откройте `http://<IP-ПК>:5000`.

## Игра через интернет

1. Соберите клиент и запустите сервер (как в предыдущем разделе).
2. Запустите tunnel:
   ```powershell
   powershell -ExecutionPolicy Bypass -File tools\tunnel.ps1
   ```
3. Скрипт напечатает `https://<id>.trycloudflare.com`: это игра целиком, её можно открыть с любого устройства. Адрес меняется при каждом запуске tunnel.

**GitHub Pages.** При push в `main` клиент автоматически публикуется (Settings → Pages → Source: *GitHub Actions*).
Откройте `https://alexandrp1902.github.io/sro2/?server=<id>.trycloudflare.com`. Адрес сервера запоминается на устройстве; сменить его можно тапом по строке статуса.
